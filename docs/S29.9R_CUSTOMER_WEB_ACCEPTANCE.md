## 2. Chẩn đoán lỗi Unit Test (Exit Code 1)

### A. Hiện tượng thực tế
Khi chạy lệnh:
```powershell
dotnet test tests/PhoneStore.Tests/PhoneStore.Tests.csproj
```
hoặc:
```powershell
dotnet test tests/PhoneStore.Tests/PhoneStore.Tests.csproj -v normal
```
Quá trình build thất bại với `Exit code 1` và hiển thị: `Build FAILED. 0 Warning(s), 0 Error(s)`.

### B. Kết quả phân tích & Nguyên nhân gốc rễ
1. **Nguyên nhân chính — Khóa tập tin DLL bởi tiến trình Web đang chạy (File Locking)**:
   - Dự án `PhoneStore.Tests.csproj` có tham chiếu `<ProjectReference Include="../../src/PhoneStore.Web/PhoneStore.Web.csproj" />`.
   - Tiến trình `dotnet watch` / Kestrel đang chạy trên host tại `http://localhost:5015` đã tải và duy trì khóa độc quyền (exclusive lock) trên các tập tin:
     - `src\PhoneStore.Web\bin\Debug\net8.0\PhoneStore.Data.dll`
     - `src\PhoneStore.Web\bin\Debug\net8.0\PhoneStore.Models.dll`
     - `src\PhoneStore.Web\bin\Debug\net8.0\PhoneStore.Business.dll`
   - Khi chạy với cờ đơn tiến trình `-m:1 /p:UseSharedCompilation=false`, MSBuild bộc lộ rõ ràng lỗi khóa:
     ```text
     error MSB3027: Could not copy "...PhoneStore.Models.dll" to "bin\Debug\net8.0\PhoneStore.Models.dll". Exceeded retry count of 10. Failed.
     error MSB3021: Unable to copy file "...PhoneStore.Business.dll". The process cannot access the file because it is being used by another process.
     ```
2. **Nguyên nhân phụ — Cách ly IPC trong Sandbox AppContainer**:
   - Khi chạy lệnh build mặc định (multi-process `/m`), MSBuild cố gắng kết nối các tiến trình worker node qua named pipes / loopback IPC. Bên trong container sandbox, cơ chế này bị hạn chế quyền khiến MSBuild hủy tiến trình âm thầm mà không ghi log chi tiết (dẫn đến thông báo `0 Warning, 0 Error`).
   - Lệnh `dotnet --info` bên trong sandbox cũng ghi nhận ngoại lệ `Access is denied (Win32Exception 5)` khi .NET SDK 8.0.427 cố gắng truy vấn Windows Service Control Manager (`ServiceController.GetDataBaseHandleWithAccess`).

### C. Phân loại lỗi
- **Loại lỗi**: `Environment / Build failure (File locking by running Web host process)`.
- **Không phải lỗi logic**: Không phát sinh lỗi biên dịch cú pháp C# và không có test assertion nào thất bại.

### D. Hướng xử lý đề xuất (ít thay đổi nhất)
- Để chạy trọn vẹn bộ Unit Test: Người dùng tạm thời dừng tiến trình `dotnet watch` trên cửa sổ dòng lệnh của host, sau đó thực thi `dotnet test tests/PhoneStore.Tests/PhoneStore.Tests.csproj`. Tuyệt đối không xóa bỏ project reference của dự án test.

## 4. Xác minh giao diện thực tế (Browser/UI Verification)

- **Trạng thái kết nối Browser Automation**: **BLOCKED**
  - Hệ thống cố gắng kết nối tới Chrome qua giao thức DevTools Remote Debugging nhưng nhận được thông báo lỗi do trình duyệt Chrome trên máy chủ của người dùng đang chạy ở chế độ duyệt web cá nhân thông thường, chưa khởi chạy cùng cờ `--remote-debugging-port` (`DevToolsActivePort` không tồn tại).
- **Trạng thái nghiệm thu Browser Automation**: **NOT TESTED** (tuân thủ nghiêm ngặt nguyên tắc không giả mạo kết quả kiểm thử giao diện khi không có kết nối browser tự động).
- **Checklist tự kiểm tra trên Chrome thông thường dành cho người dùng**:
  1. Mở `http://localhost:5015/` trên trình duyệt Chrome (zoom 100%): Kiểm tra Header, Footer, Hero banner, logo thương hiệu và các thẻ sản phẩm.
  2. Mở `http://localhost:5015/products`: Kiểm tra hiển thị 10 sản phẩm (5 cột × 2 hàng), thử nghiệm thanh tìm kiếm và bộ lọc sidebar.
  3. Mở `http://localhost:5015/products/1`: Kiểm tra ảnh gallery, bảng thông số kỹ thuật 2 cột.
  4. Mở `http://localhost:5015/account/login` & `/account/register`: Kiểm tra card compact 480–540px, đảm bảo không có khung cảnh báo lỗi đỏ rỗng.
  5. Nhấn `F12` $\rightarrow$ Chuyển sang kích thước iPhone 12/13 (390px): Kiểm tra thanh menu `.main-nav` cuộn ngang mượt mà, không xuất hiện thanh scrollbar xám, không tràn ngang.
