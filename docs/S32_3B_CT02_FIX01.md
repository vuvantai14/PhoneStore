# S32.3B-CT02-FIX01 — PASS source/automated; runtime pending

Verified 2026-11-16. No deployment or live SQL writes in this task.

## Root cause

`PhoneStore.Cart` and `PhoneStore.CheckoutToken` were independent of the auth cookie, with no owner. Explicit logout cleared both. Cookie validation rejected disabled/changed accounts via sign-out only, leaving session data. Expired/unreadable cookies can bypass ValidatePrincipal altogether. Login did not bind cart/token to the authenticated identity, so B could inherit A's browser-session cart/token.

## Fix

- `SessionCart` adds `PhoneStore.CartOwner` and checks ownership on read/write/token operations.
- Owner A -> anonymous or B clears cart and checkout token. Same owner retains cart/token.
- Anonymous -> authenticated adopts the anonymous cart, preserving existing shopping behavior, but rotates the checkout token.
- Middleware after authentication and before authorization reconciles ownership on every MVC request, including protected requests rejected by authorization. Thus expired, revoked, disabled or invalidated cookies are handled without depending solely on a cookie callback.
- Successful login explicitly binds ownership before issuing the new cookie. Explicit logout cleanup remains unchanged.
- No cookie format, auth contract, schema, pricing, order/stock or checkout-idempotency logic changed.
